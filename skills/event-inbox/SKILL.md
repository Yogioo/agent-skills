# Event Inbox

A small durable queue of event records. Each event is one JSON file under an
explicit `--dir`; callers write an event and later ack it. Writing an event
never starts a process, sends a notification, or changes any other record.

Use `node <skill>/scripts/inbox.mjs --help` for options and exit codes.

```powershell
node <skill>/scripts/inbox.mjs emit --dir <store> --file <event.json>
node <skill>/scripts/inbox.mjs emit --dir <store> --stdin
node <skill>/scripts/inbox.mjs list --dir <store> [--state unread] [--project <key>] [--requirement <id>] [--kind <kind>] [--unrouted]
node <skill>/scripts/inbox.mjs get --dir <store> --id <id>
node <skill>/scripts/inbox.mjs ack --dir <store> --id <id> --state seen --note "woke up"
```

## Contract

- `emit` accepts a JSON object with `kind` (required) and optional
  `projectKey`, `requirementId`, `workItems`, `title`, `detail`, `nextStep`,
  `workdir`. They are stored as opaque metadata: the inbox never derives a
  project from the current directory and never routes events.
- IDs are generated by the store (timestamp + kind + scope + random bytes) and
  retried if a filename collides. IDs and paths are validated so a caller
  cannot escape `--dir`.
- State is monotonic: `unread` < `seen` < `done`. `ack` only accepts `seen` or
  `done`; writing a lower state is an error. A repeated ack of the same state
  with no new note is idempotent: it writes nothing and leaves `updatedAt`
  unchanged. Any real transition advances `updatedAt` by at least one, even
  across processes and clock ties.
- `list` reports valid events in `items` and unreadable `.json` files in
  `invalid`, so corruption is visible instead of looking like an empty store.
  `get` rejects a corrupt record as an invalid-record error.
- Files are replaced atomically (unique temp file + rename). Mutations hold a
  per-store writer lock (`.write.lock`); a lock held by a live process produces
  an explicit busy failure. Acquisition never removes an existing lock. After a
  crash, stop all writers before inspecting and removing a leftover `.write.lock`.

## Programmatic use

`scripts/inbox.mjs` exports `writeEvent`, `listEvents`, `getEvent`, and
`ackEvent`, plus `INBOX_STATES` and the `EventInboxError` class. All source is
self-contained (Node built-ins only).

Exit codes: `0` success (exactly one JSON value on stdout), `1` operational
failure (including a missing record), `2` invalid arguments or invalid/corrupt
records.
