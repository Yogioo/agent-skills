tapd-loop 链路

一条命令从读到配置，到一张卡被推上去、写回 TAPD，中间经过谁、动了什么、在哪判定。依据是当前的 loop.mjs / turn.mjs / tapd.mjs。

外循环 · node 进程 内循环 · pi 子进程 TAPD · tapd-cli 仓库 · git 看板 · 只读 HTTP 出口 = 离开主流程
  1. 启动：一次性准备，和卡片无关

  2. 外循环解析参数，叠出最终配置

    • 五层覆盖：内置默认 → ~/.tapd-loop/config.json → <git-common-dir>/tapd-loop.json → --config 文件 → 命令行参数
    • 仓库级配置在 .git/ 里，所以工作区永远干净；同一个仓库的所有 worktree 共用这一份
    • 仓库根的老位置 .tapd-loop.json 仍能读但会告警，--migrate-config 搬进 .git/
    • 没有 task.assignee 直接报错（--fetch 除外）
    结果 cfg 对象，附 cfg.sources 记录每层文件路径与是否命中

  3. 外循环开通道、查仓库、建运行目录

    • createTapd()：workspace、状态 key 表、四个机器标签名
    • 必须是 git 仓库；工作区脏就拒跑（--dry-run / --migrate-config / --allow-dirty 除外）
    • runDir = ~/.tapd-loop/runs/run-<时间戳>/，之后所有事件按行追加到 progress.jsonl

  4. 看板拉起常驻进程，拿到一个固定地址

    start-board.mjs 用 detached 子进程起 serve.mjs，绑 127.0.0.1:7317，地址写进 ~/.tapd-loop/board.json。已在跑就复用。

    起不来只打一条日志，不影响干活，只是没页面可看

  5. 外循环两个提前退出的口

    • --dry-run：打印 sources、cfg、队列，然后退出。不建 runDir、不动 TAPD
    • push 闸门：push.enabled 但 verify 为空 → 启动即报错。等一张卡跑完二十分钟才告诉你，代价太大
  6. 每一轮：先看还要不要跑，再挑一张卡

  7. 外循环三个停止条件

    每分钟一轮：<git-dir>/tapd-loop-stop 存在（每棵树独立）→ maxTasks 到量 → maxFailures 连败。任一成立就跳出。

  8. TAPD拉队列，挑第一张能做的

    • story list owner=<处理人> label=ready-for-agent
    • 过滤掉带任何机器标签的（afk-claimed / afk-delivered / afk-failed）
    • 按优先级、再按 id 排序，取第一张状态在 developing / status_11 的
    队列空没开 --watch 就结束本轮循环；开了就睡 pollSec 再轮

  9. 外循环进入 runCard()，再查一次状态

    列表到开工之间可能被人改过，所以在跑任何前置之前先确认状态还在范围内。

    状态已变记 skipped，回去拿下一张，不算失败

  10. 仓库开工前同步：git pull --rebase

    • 必须是开工前的第一步：rebase 会改写历史，等基线取完再 rebase，失败回滚就会把刚拉到的上游 commit 一起抹掉
    • 工作区停在半截 rebase / merge / cherry-pick 时，先按标记文件清干净再继续
    • 冲突文件用 git diff --name-only --diff-filter=U 取，网络类失败自动重试 sync.retries 次
    • 每次同步的 moved / from / to 都记进 progress.jsonl
    冲突或未跟踪文件挡住上游同名文件 → rebase --abort，这张卡记 blocked，整批停。同一个坏基线上继续跑下一张只会重复浪费内循环
    只是没 upstream / detached / 已跟踪文件脏 → 记一条跳过日志，照常开工

  11. 仓库afterSync 护栏：修好机器人看不见的脏状态

    • DigitDoor 填 bash Tools/GitHooks/Luban/after-update.sh；无条件每张卡跑一次，不是「sync 真动过才跑」
    • 理由：脏导出不只由本循环造成。人在外面 rebase / cherry-pick / reset 都不触发 git 的 post-merge / post-checkout，而导表守卫挂在那两个钩子上
    • 跑完比对 git status：护栏自己留下新改动也不行，那些会被 add -A 算进本卡提交
    护栏失败或留下脏改动 → 记 blocked，整批停。导出是旧的，开了工也白做

  12. 仓库记下基线 baseline = git HEAD

    这张卡后面所有的「有没有改动」判定，和失败时的回滚，都以它为锚。到这里仓库历史才可以被认为稳定。

  13. TAPD占住这张卡：加 afk-claimed

    多份拷贝并行时靠它互斥，谁先加谁拿到。写标签一律回读校验，多值字段用竖线分隔。

    占不到（已有别的机器标签 / 状态被改回）→ 记 skipped，换下一张

  14. TAPD抓工单，落成本地素材

    • 读正文 + 全部评论，HTML 转纯文本
    • 正文里的 /tfl/ 内嵌图：attachment get-image 换签名地址再下载，最多 30 张，正文改写成相对路径
    • attempt = 正文里 [tapd-loop] 失败 出现次数 + 1，用来告诉内循环这是第几次
    产出 card.md（人看） · card.json（机器看） · images/
    读取失败 → 进失败出口，回滚到基线

  15. 外循环拼 brief：只讲这张卡和边界

    • 写「工作目录、这张卡是什么、边界、怎么算完成、最后输出什么」
    • 不写技能正文，也不写「去读 SKILL.md」。技能正文由下一步 pi 直接注入
    • 边界原文：只改本卡范围 · 不要执行任何 git 命令 · 不要问人 · 不留调试代码 · 结尾给 RESULT: 与 COMMIT: 两行
    产出 brief.md
  16. 交给内循环：从这一步开始模型介入

  17. 内循环起一个 pi 子进程，技能正文由 pi 自己读进去

    命令长这样：

    • --append-system-prompt <SKILL.md 路径>：给路径时 pi 读的是文件内容，正文确定性地进系统提示
    • --skill <yogioo-mode>：只登记 name/description/path。光靠它正文进不来（实测：系统提示里搜不到 Non-negotiables），而且这个技能还带 disable-model-invocation: true
    • @brief.md：brief 正常情况下展开成用户消息
    • stdout 全量落 events.jsonl，stderr 落 pi.log；超时用 taskkill /T /F 连子树一起杀
    这里跨过了进程边界：两个进程、两个模型上下文，外循环看不到里面怎么想，只能事后读事件流

  18. 内循环自己把活跑完，外循环不干预

    • 按已注入的指令选 playbook（Bug fix / Feature / Investigation …），把步骤抄成清单
    • 需要并行就把调查拆给 agent-tools subagent 的只读 arm
    • 改代码，用 Unity MCP 复现与验证，跑相关 EditMode 用例
    • 不碰 git：只在工作区留下改动，结尾输出 RESULT / COMMIT
    产出 工作区改动 + events.jsonl（可能几十 MB，含每一次工具调用）
  19. 判定：只信客观信号，不信模型自述

  20. 外循环四道闸，按顺序过

    1. 进程超时了吗（timedOut）
    2. 事件流里有 agent_settled 且没 aborted 吗
    3. git.changedSince(baseline)：工作区脏 或 HEAD 动了
    4. 配了 verify 的话，退出码是不是 0（输出落 verify.log）
    任一条不过 → 写 diff.txt 存档 → reset --hard baseline + clean -fd → 撤 afk-claimed、加 afk-failed → 评论原因 → 记 failed
  21. 提交与推送：这一段里 git 历史会被写两次

  22. 仓库提交

    • 工作区有改动就 git add -A + commit
    • message 从内循环那行 COMMIT: <type>:<7位工单号> <描述> 取；工单号必须是卡片 id 后 7 位，对不上就用卡片标题兜底
    • 不带 AI 署名，不写 19 位全 id
    • diff.txt 在推送之前就落盘：之后一旦 rebase，旧 commit 可能变得不可达

  23. 仓库再同步一次，然后 git push

    • 卡跑了十几到几十分钟，期间别人可能又推了，所以推之前必须再造一次 pull --rebase
    • 最多 push.retries + 1 轮；网络抖和 rejected / fetch first 算可重试，分支保护不算
    • 永不 --force。共享分支上强推等于删别人的提交
    • 推送关着时这一步直接跳过，记为「未开启 push」
    同步冲突 / 远端拒绝 → 不丢活也不留在当前分支：提交挑到 tapd-loop-unpushed/<卡片id>，当前分支退回父节点，加 afk-failed，评论写出分支名。留在当前分支的话，下一张卡的 push 会把它一起带上去，而 TAPD 上写的是「未推送」
    verify 为空（且没写 allowUnverified） → 这种在启动时就被拦了，走不到这里
  24. 回写：到这一步结果才定型

  25. TAPD换标签，发验收评论

    • 撤 afk-claimed，加 afk-delivered（多值字段，写完回读校验）
    • 评论 = 抬头 + 结论前 2000 字（按句子边界截）+ 推送后的 HEAD + 证据路径
    • 标出来源：提交：c1ddebbae（已推送 origin/develop） 或 提交：f1a28b8c9（未推送，留在本地：…）

    sha 必须在推送之后取：rebase 会改写 sha，commit 那一刻的 sha 在推完之后可能已经不存在于远端。

    评论写失败只记 warning，不回滚——代码已经在远端了

  26. 看板页面始终能看全过程

    左侧每次 run 的队列，点卡开窗：工单（含图）、主 Agent 结论、brief、验证输出、diff、进程日志尾部、子代理、事件时间线。2 秒刷新，只读，绑 127.0.0.1。

  27. 收尾：跳出循环，把这一轮汇总

  28. 外循环写报告，打一行 JSON 摘要就退

    • 退出原因：stop-file / max-tasks / max-failures / blocked / empty-queue
    • report.md：每张卡一行状态与说明
    • stdout 一行 JSON：attempted / done / failed / blocked / runDir / reportFile / ledger
    每张卡的目录 card.md · card.json · images/ · brief.md · events.jsonl · pi.log · verify.log · after-sync.log · diff.txt

一张卡的六种结局

结局什么时候改动去哪了整批
done四道闸全过，提交、推送、回写都成已在远端继续
done（未推）同上，但 push 关着在本地当前分支继续
skipped状态不在范围、占不到卡无改动继续
blocked同步冲突、afterSync 红、护栏留脏无改动停
failed（提交前）超时、没 settled、无改动、verify 红回滚到基线，丢掉计数
failed（提交后）推送前同步冲突、远端拒绝在 tapd-loop-unpushed/<id>计数

分界线是「提交有没有发生」。提交之前回滚是安全的；提交之后回滚等于把这张卡干出来的活扔掉，所以换成挑到具名分支。

两个循环的分工

外循环（tapd-loop）内循环（yogioo-mode）
是什么一个 node 脚本，跑完就退一个 pi 会话，被外循环 spawn
管什么取卡、同步、判定、提交、推送、回写想清楚、改代码、自己验证
模型参与没有全程
git 写操作sync / commit / push / rollback禁止
TAPD 写操作标签、评论禁止
怎么算成功进程正常 + 有改动 + verify 过（+ 推得上去）自己说 RESULT，但不算数

三个值得单独记住的约束

约束为什么
rebase 只能发生在两个位置：开工前、提交后它改写历史。基线取完再 rebase，失败回滚会把上游 commit 一起抹掉
技能正文靠 --append-system-prompt，不靠模型自觉 read--skill 只登记名字/描述/路径，不注入正文；不注入就等于 AI 没拿到指令
推之前必须有 verifypush 把外循环从「产物留本地」变成「往共享分支发布」，没验证过的改动不该自己进去
读这张图的方式　蓝色 = 确定性代码，紫色 = 模型在跑，橙色 = 动 TAPD 数据，绿色 = 动 git 历史。 紫色那段是唯一不可控的，所以判定全压在它之后的蓝色步骤上，且只认进程、git、verify 三个客观信号。
