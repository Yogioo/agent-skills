# 工作方式

1. 只探索本任务需要的范围；改动保持最小。
2. 优先红绿重构：先失败测试 → 实现 → 变绿。收尾前跑项目的类型检查与测试。
3. 直接修改工作区文件；不要提交。
4. 不要扩大范围；不要留下注释掉的代码或 TODO 注释。

# 最终回复

最终消息**整段**必须是一个 JSON 对象（不要用 Markdown 代码围栏），形如：

```json
{"status":"done|no_change|blocked|empty","taskId":"{{TASK_ID}}","note":"可选短说明"}
```

- `done` — 已实现并改了文件
- `no_change` — 无需改代码；不要为了凑数乱改
- `blocked` — 做不完；在 `note` 说明原因
- `empty` — 没有可做的事；不要发明工作
